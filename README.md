# Road to the Final ⚽🏆

A fun, animated tracker for the FIFA World Cup knockout stage — Round of 32 through
the Final — built with React, TypeScript, Vite, and Framer Motion.

## Features

- Live World Cup 2026 knockout results are fetched server-side (in CI, see
  "How it works" below) from [football-data.org](https://www.football-data.org/)
  first, falling back to [TheSportsDB](https://www.thesportsdb.com/), and
  published as a static JSON file the app reads. Fetching happens server-side
  on purpose: football-data.org doesn't allow direct browser calls (no CORS),
  and a static site has nowhere safe to hide an API key from the browser anyway.
- Falls back to a bundled snapshot of the real knockout bracket (see
  `src/data/fallbackBracket.ts`) if no live source responds, so the app always
  shows the actual matchups. The status badge always says plainly which one
  you're looking at, with a "Why offline data?" toggle showing the actual error
  from each source.
- Symmetric knockout bracket of flag tiles fanning out to a central champion,
  with winner highlights and a confetti celebration when a champion is crowned.
  Tap any match for its round, score, kickoff date and venue.
- Live/offline status badge with a manual refresh button, and auto-refresh every 60s.
- Installable as a Progressive Web App — add it to your phone's home screen
  for a full-screen, app-like experience with an offline-capable service worker.

## Install it on your phone

There's no `.apk` — instead the app is a installable PWA, which works on both
Android and iOS without any app-store build:

1. Open the deployed/preview URL on your phone's browser (must be served over
   HTTPS, or `localhost` for local testing).
2. **Android (Chrome)**: tap the ⋮ menu → "Add to Home screen" / "Install app".
3. **iOS (Safari)**: tap the Share icon → "Add to Home Screen".
4. Launch it from the home screen icon — it opens full-screen, no browser chrome.

## Getting started

```bash
npm install
npm run dev
```

Then open the printed local URL in your browser.

### Getting real live data (recommended)

The browser only ever reads a plain `data/worldcup.json` file — it never calls
football-data.org or TheSportsDB directly. That file is generated by
`scripts/fetch-matches.mjs`, which needs to run before a build:

1. Register for a free API key at
   [football-data.org/client/register](https://www.football-data.org/client/register)
   (takes about a minute, no credit card).
2. Locally:
   ```bash
   export FOOTBALL_DATA_API_KEY=your-key-here
   npm run fetch:data   # writes public/data/worldcup.json
   npm run dev
   ```
3. For the GitHub Pages deployment, add the key as a repository secret named
   `FOOTBALL_DATA_API_KEY` (Settings → Secrets and variables → Actions → New
   repository secret) — the deploy workflow already runs `fetch:data` with it
   before building, and re-runs on a schedule to keep results fresh.

The key never reaches the browser or the built JS bundle — it's only used by
the Node script during the CI build.

## How it works

- `scripts/fetch-matches.mjs` — run server-side (locally or in CI). Tries
  football-data.org, then TheSportsDB, and writes the result (including any
  error messages) to `public/data/worldcup.json`.
- `src/api/worldCupApi.ts` — fetches that static JSON same-origin, falling
  back to `src/data/fallbackBracket.ts` if it's missing or empty.
- `src/utils/rounds.ts` — maps raw round names to a canonical order/label/emoji.
- `src/utils/flags.ts` — converts country names to flag emoji.
- `src/components/RoadToFinal.tsx` — groups matches by round and renders the
  animated timeline, triggering confetti via `useChampionConfetti` once the
  Final has a result.
